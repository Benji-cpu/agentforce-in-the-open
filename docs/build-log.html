Agentforce in the Open

Testing a support agent against synthetic orders: what it answers, what it actually does, and where it still fails. A Developer Edition prototype, not a customer deployment.

What this tests

A customer should get an order status from the right record, a clear refusal when details do not match, and a real route to a person when the agent cannot help. A convincing reply is only one part of that test. Read the short explanation and evidence.

I was the Salesforce application architect at BVNK — London crypto payments — for four years: B2B and B2C onboarding with KYB and KYC, Flows, integrations. Before that, a Service Cloud migration at Coindirect. I have been out of a Salesforce org since 2023, and spent the two years since building AI agents full time — production agents, MCP servers, the unglamorous plumbing underneath them.

What I have never done is ship an Agentforce agent. Not one, not in a sandbox that mattered. That is the premise of this log rather than a thing to keep quiet about: the certifications say I know the platform, the last two years say I know agents, and the join between the two is exactly the gap I am closing in public.

Sales Cloud and Service Cloud are the clouds I have actually worked. No Marketing Cloud, no Data Cloud. If you catch me claiming otherwise anywhere, that is a mistake and I want to know about it.

01 15 Sep 2026

A captcha beat me before Agentforce got the chance

Set out to do

Get a link up before there is anything to show on it. Open this log, stand up a public repo, install the Salesforce CLI, and sign up for the free Agentforce Developer Edition org.

What happened

Three of the four. The log went up first, on purpose — a build log written after the build is a press release. The repo is public at Benji-cpu/agentforce-in-the-open, and docs/capture/ started collecting terminal output before a single thing was installed, because the state of a machine with no Salesforce tooling on it cannot be reconstructed afterwards.

The CLI took eighteen seconds and 714 npm packages, and brought a surprise with it: the Agentforce plugin is not a plugin any more. agent 1.45.0 (core) ships inside the CLI, so sf agent is there the moment the install finishes. Most walkthroughs still tell you to install it separately.

Then the org. I drove the signup form from a script — every field green, the agreement ticked, the button clicked — and it has been saying Please wait.. ever since.

The number

0network requests sent in 43 seconds of “Please wait..” — the form never called Salesforce at all

What broke

Two things, and they are different animals. First, www.salesforce.com sits behind Akamai, which serves a headless browser 403 Access Denied and a headed one 200. Same script, same machine, same address — one flag between them.

Second, and this is the real one: the form loads recaptcha/api.js with an onload callback that never fires, so window.grecaptcha stays undefined, the submit handler waits on a token that will never arrive, and nothing is ever sent. navigator.webdriver is true — this browser is honestly labelled as automated and is not pretending otherwise.

That is a captcha doing its job, so it stays undefeated here. Ninety seconds of a human's hands finishes it. There is a lesson for anyone automating Salesforce onboarding in that sentence, and it is not a complaint about the captcha.

The org, signed up by hand, then sf org login web and the first sf agent command run against it. After that, a small synthetic business to ground the agent in — named as synthetic every time it appears here.

One thing worth coming back to: the signup page sells the org on “connect Claude Code, Cursor or Codex to your org with hosted MCP” and 60-plus MCP tools out of the box. I build with Claude Code every day and had not seen that. If it works as advertised it is the first Teardown.

02 15 Sep 2026

Agentforce was switched off in an Agentforce org

Set out to do

Get the org authorised to the CLI, and get something that is genuinely agent source — not a screenshot of a builder — into the repo.

What happened

The captcha took a human about ninety seconds, as advertised. Then four things in a row, none of them the thing any quick start warns you about.

The CLI installs on Node 20 and then dies on it. Its bundled undici calls webidl.util.markAsUncloneable, which arrived in Node 22. npm said nothing at install time. There is now a three-line ./sf wrapper in the repo that puts a keg-only node@22 on PATH for that command and leaves the machine default where the other projects need it.

sf org login device does not exist in v2 — that was sfdx — and SF_CONTAINER_MODE refuses the web flow outright rather than printing a URL. So: the web flow, with the auth URL handed to the browser that already held the session.

Then the real one, below. After it: four topics drafted by the org's own model, an Agent Script authoring bundle written into force-app/, and a clean compile. The blueprint is a file you can read, diff and deploy, which is the whole reason for doing it this way.

The number

3 of 4business subagents in the generated bundle carry the same boilerplate instruction — “help the user track their order” — including the one about returns and the one about calibration certificates. It compiled with 0 errors in 2.56s.

What broke

Agentforce was off in a Developer Edition org signed up specifically for Agentforce. The CLI's error was This feature is not currently enabled for this user type or org: [AgentforceAiAssist], which does not say where to go.

Three places looked like the answer and were not. Einstein Setup says “Turn on Einstein: On” and means something else. sf org list metadata-types returns GenAiPlannerBundle, GenAiPlugin, GenAiFunction — all present, which reads like the feature is live. And BotDefinition is not a queryable object, which looks like a permissions problem.

It is one toggle at Setup → Einstein → Agentforce Studio → Agentforce Agents, reading Off. The part worth keeping: that switch has no metadata representation. It cannot be deployed, committed, or included in a handover repo. Anyone shipping an agent to a client has a click in their runbook whether they like it or not, and it had better be written down.

03 15 Sep 2026

Seventeen of twenty, and every miss was the same miss

Set out to do

Make the agent do something. Real instructions for the four subagents, one real action that looks an order up, a synthetic dataset behind it, then twenty questions and a count.

What happened

All of it, and the count moved three times. The action is an invocable Apex class, NorthavenOrderLookup: order reference and email in, status, carrier, tracking, delivery date and certificate status out, and nothing out unless both match. Behind it, seven custom fields on the standard Order object and twelve invented orders for eight invented customers — Northaven Instruments does not exist, and neither does Whitcombe Academy.

Getting it into the org took three deploys where one should do. Tests that run in the same deployment as new fields cannot see the fields. A metadata deploy grants the deploying user no field-level security, so the data load would have written nothing into them. And the Einstein Agent User's licence refuses View All on Order and Account outright, so the permission set had to stop asking.

Then the first conversation. “I am checking the status of your order NI-2041. I will update you as soon as I have the details.” It was not checking anything. The trace showed the model was offered three transitions and no lookup: the agent user did not yet hold the permission set that grants the Apex class, and the runtime does not raise an error for that. It removes the tool from the menu and lets the model improvise. With the permission in place the same question came back with the carrier, the tracking number and the date.

Twenty questions, one fresh session each, driven through a small script around sf agent preview so every transcript and trace is saved. Round one: fifteen answered, two escalated, three wrong. Two instruction edits fixed two of the three. Round two: seventeen, two, one. The last one is question 19, a customer asking for a person. The agent said “I am passing this to a person now” and did not. Salesforce's own pattern library has a name for this — promised human handoff — and a structural fix: put @utils.escalate in the router itself. Round three: question 19 hands over. Question 18, which had escalated twice, now narrates instead. Seventeen, two, one.

Then sf agent publish: 44.9 seconds, and the org holds Northaven_Support v1.

The number

17 · 2 · 1answered, escalated, wrong — of twenty, after three rounds (15·2·3, then 17·2·1 twice with a different wrong). The lookup ran on all 33 turns that needed it. No wrong facts. Correction, 16 Sep: traces show 12, 13 and 13 lookup calls, including six negative lookups. Round-one question 2 never called it. A claim that an action happened is itself a factual claim. These were preview runs, not received human handoffs.

What broke

The lookup was absent from the available tools. In this captured preview, missing Apex access produced no conversation-level permissions error. The reply promised a lookup anyway. The lesson is to inspect execution and access together; this single observation does not describe every permissions failure.

The org's own judge got it wrong. Each turn carries a guardrail verdict. On question 19 it read FULLY_RESOLVED for a turn in which the only tool offered was the escalation and it was not called. The verdict scores the words. Scoring has to read the trace.

Fixing the promised hand-off in one place moved it to another. The subagents still hold a two-step route to a person — transition to an escalation subagent, then call — and the model narrates that route rather than walking it in some of these development cases. Three rounds with changing instructions cannot establish a failure rate. The 16 September review gives those subagents a direct escalation action and repeats the check.

Knowledge is not enabled in this org, so the three policy topics are grounded in the subagent instructions, not in articles. That is a limitation and it is written down as one.
